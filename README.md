# 门店业务与总部数据系统

当前前端版本：`0.15.0`

## 腾讯云客户人脸识别后端

`cloudfunctions/faceRecognition/` 是 CloudBase 云函数源码。它使用腾讯云人脸识别的人员库与人脸搜索能力，人员库 ID 为 `lusizhuoerdatabase`；客户首次授权建档时录入人脸，后续核销可搜索匹配客户。函数密钥只能配置在 CloudBase 环境变量 `FACE_SECRET_ID`、`FACE_SECRET_KEY` 中，严禁出现在网页代码、GitHub 或文档中。

前端通过已登录 CloudBase UID 调用云函数，门店、总部及客户范围均在服务端重新校验。正式处理真实人脸数据前仍必须确认活体检测服务、客户明确授权、人脸数据删除渠道和访问审计均已启用。

## 员工登录与账号唯一性

- 一个中国大陆手机号只能绑定一个业务身份；手机号码全局唯一，已绑定后不可再次注册或改绑给其他总部、运营、门店或老师身份。
- 账号创建仅由已授权总部在网页端发起；后端同时创建身份认证用户与业务档案绑定记录。未预先绑定的手机号不能通过短信自助注册进入系统。
- 员工可使用“手机号 + 密码”或“手机号 + 短信验证码”登录；两种方式对应同一身份和同一权限，不产生第二个账号。
- 修改密码须由当前已登录用户完成短信二次验证；总部可发起重置，系统记录操作人、时间和原因。初始 12 位密码仅作首次/应急登录凭据。

## 总部基础资料创建规则

- 门店创建为独立页面；填写门店名称、完整地址，并可添加多组联系人姓名与电话。提交后自动生成门店编号、门店账号与12位数字初始密码。
- 老师和运营人员创建必须填写姓名、身份证号码和联系电话；系统自动生成编号，身份证号码在老师和运营人员的完整人员库中不可重复。同名时显示名称自动追加 `+1`、`+2` 等顺序号。
- 老师管理和运营管理支持按姓名或身份证号码查询；按姓名查询时，结果同步显示身份证号码以确保唯一定位。两个页面只支持封存，不提供删除操作。
- 总部侧栏不再设置“创建”菜单；门店、产品、老师与运营人员均只能从各自管理页的“新增”按钮进入创建页。
- 门店管理首次进入仅提供“门店名称＋省/州＋城市＋区”选择和新增门店；确认选择前不显示门店资料。确认后展示门店信息、统计和“查看门店页面”入口；同名门店自动以 `1`、`2`、`3` 区分。
- 示例门店统一使用中国省、市、区；新建门店时省、市、区为联动下拉选择。完整三级行政区划数据保存在本地 `china-regions.js`，离线打开原型时同样可用。
- 门店管理还支持手动输入门店名称并依次选择省、市、区；系统先弹出详细地址和联系人方式供核对，确认无误后才跳转至门店页面。
- 产品管理一次展示全部产品；点击某个产品后才显示其资料、门店统计和独立产品页面入口。
- 核销办理和补录核销均使用人脸识别核验，不再要求拍照；只有活体检测与人脸比对通过后才能提交核销，正常核销才会发送设备开启信号。
- 充值不需要人脸识别，也不采集刷脸或拍照凭证；确认客户、项目和充值次数后即可提交审核。
- 门店账号和运营账号密码仅总部可在对应管理页面查看或修改；静态原型中密码仅保存在当前浏览器会话，正式部署须改由后端保存密码哈希并记录审计日志。

直接双击 `login.html` 或运行 `open-dashboard.cmd` 即可离线打开统一登录入口，不需要安装依赖或启动服务器。
登录页按“总部、运营、门店”的顺序显示三个身份选项；门店登录必须选择所属门店。静态版接受任意非空密码，
只在当前标签页的会话存储中保存单一演示会话，不保存密码；重新选择身份登录时先清除上一身份会话，避免角色状态混用。
总部进入数据库全局工作区；运营只进入显示本人数据库资料的全局视图，并只保留充值审核与核销审核；门店直接进入所选门店工作区。未登录访问业务页面、直接输入其他身份页面地址、
或者门店修改URL中的门店编号时，`auth-ui.js` 都会拦截并返回本身份首页。侧栏只生成当前身份允许的入口，并提供账号、门店及退出登录。
总部的客户、充值和核销查询使用同一套数据库页面，可查看全部门店或选择一个具体门店；门店账号的三类查询固定锁定到登录门店，不能选择“全部门店”或其他门店。页面选项只决定筛选条件，最终权限仍由云函数根据 CloudBase UID 校验。
前端路由隔离不是安全边界：`staffAccount`、`faceRecognition` 和 PostgreSQL RLS 都会再次按 CloudBase UID、账号状态和角色校验。运营账号不能调用客户查询、门店、产品、管理或总部统计接口；只能从真实审核记录进入受工单上下文约束的客户与业务只读详情。

门店工作区侧栏新增“业务办理”：

- `customer-create.html`：客户建立，必填姓名、生日，强制现场拍摄建档照片，保留面容录入、活体/质量检查与授权逻辑，并填写特别注意事项；
- `recharge-create.html`：办卡充值，可选择现有客户并自动带出只读生日，或手动输入姓名和生日；只匹配本门店活跃客户，确认后选择项目和次数，并强制完成现场扫脸拍照；
- `verification-create.html`：核销办理，沿用本门店活跃客户检索，选择项目和老师，现场照片成功后才允许核销并发送虚拟端口信号。

办卡充值和核销办理的客户区提供两种检索模式：“现有客户下拉框＋生日”以及“手动输入姓名＋生日”。现有客户模式选择带编号的客户后，生日由客户主档自动带出并保持只读，不能在查找流程中修改；只有手动模式允许选择生日。查询后左半栏显示
客户建档时拍摄的当前有效照片、姓名、生日和客户编号，不再显示各项目剩余次数；必须点击“确认此客户”后右半栏才解锁。建档照片不存在或读取失败时不得确认客户。
切换方式或修改条件会撤销确认并重新锁定。
核销项目下拉框只加载剩余次数大于零的项目，并直接显示剩余次数。

静态原型只保存当前标签页中的演示状态，不采集真实面容或照片。正式部署时，客户和门店范围必须由服务端会话确定，
面容录入必须使用受控摄像头、活体检测、质量检查、加密模板和授权审计，不能由前端自行声明成功。
客户建立、办卡充值和核销办理页面在桌面端使用尽量占满可用工作区的拉伸布局；充值和核销采用左右双栏，
左侧持续显示客户检索结果，右侧完整显示项目、次数、采集状态和提交结果，窄屏时自动切换为单栏。

项目栏中的“管理”可以展开三个子页面：

- `store-management.html`：新增、选择、查看和删除/停用门店；查看老师核销表、项目核销表和本门店全部客户项目次数；
- `project-management.html`：新增、选择、查看和删除/停用项目；查看项目在各门店的充值与核销统计；
- `teacher-management.html`：新增、选择、查看和删除/停用老师；查看老师在各门店、各项目的核销统计。

每个门店都有独立的 `store-detail.html` 页面。门店管理页提供“查看门店页面”按钮；项目统计、老师页面、
充值/核销查询和业务详情中的门店可以点击进入对应门店页面。总部从门店管理进入时以真实数据库门店 ID 读取所选门店，门店账号进入时由服务端 UID 锁定自身门店；基础资料、项目统计、老师统计和分页客户均来自同一门店看板数据库接口。

每个项目都有独立的 `project-detail.html` 页面。项目管理页提供“查看项目页面”按钮；门店页面、老师页面、客户档案、
充值/核销查询和业务详情中的项目可以点击进入对应项目页面。项目页面显示基础资料、设备权限代码、门店老师统计、客户权益和档案审计。

门店客户表中的每个客户编号均可点击并进入 `customer-detail.html`。客户详情页当前按常规后台档案设计，显示基础资料、
全部项目权益、充值记录、核销记录、异常修改/删除审核、照片权限说明和档案审计；不同项目不覆盖，旧版本和原始记录继续保留。

每个老师都有独立的 `teacher-detail.html` 页面。老师管理页提供“查看老师页面”按钮；门店老师核销表、核销查询、
客户核销记录和核销详情中的老师编号均可点击进入对应老师页面。老师页面显示基础资料、关联门店与项目、
核销统计、最近核销明细、照片/资格附件权限说明和档案审计。
客户详情页使用URL客户编号参数定位对象，后续部署时由后端按登录权限读取对应真实档案。

门店项目栏新增“业务管理”折叠菜单，其中“客户管理”锁定到登录门店。客户可以按照“全部客户、有信息但没有充值、已充值但没有消费、已充值并已有消费”四档业务阶段，
以及“全部、活跃、已存档”三档客户状态组合查询。

项目栏新增“查询”折叠菜单：

- `customer-query.html`：数据库客户查询，业务阶段统一为“有信息但没有充值、已充值但没有消费、已充值并已有消费”三类；总部可选全部或指定门店，门店锁定本店，并支持活跃、已存档和恢复；
- `recharge-query.html`：数据库充值查询，总部可选全部或指定门店，门店锁定本店，分别显示原单状态与作废申请状态；
- `verification-query.html`：数据库核销查询，总部可选全部或指定门店，门店锁定本店，分别显示核销类型、原单状态、作废申请状态和人脸核验记录。

门店账号无权删除任何客户，也无权修改姓名、生日或其他客户资料。客户编号、姓名、生日、所属门店、照片、人脸信息、项目权益、次数和审计字段在门店客户端全部只读。
门店唯一允许的客户管理操作是把活跃客户设为存档，或把已存档客户恢复为活跃；每次状态变更均记录账号、门店、原状态、新状态和时间。
存档不会删除充值、核销、版本、照片或审计记录，已存档客户可以重新查询并恢复。
办理充值或核销时使用“客户姓名＋生日”组合查找，门店条件由登录会话锁定，并且只返回活跃客户；
同名同生日客户通过客户编号区分。办理页面的活跃客户检索与充值、核销历史查询相互独立；历史查询另行提供现有客户精确选择和手动姓名匹配两种模式。

项目栏新增“审核”折叠菜单：

- `recharge-review.html`：审核新充值，以及充值修改和删除申请；
- `verification-review.html`：审核核销确认，以及核销修改和删除申请。

两个审核页按门店、申请类型和审核状态筛选，支持通过、驳回和必填审核备注。
审核记录显示发起门店、账号和人员姓名。总部与运营均可点击工单号进入业务详情，也可点击客户进入客户主页；运营的详情入口只作为审核下级页面，不生成查询或管理菜单。运营客户主页必须携带真实审核工单上下文，服务端校验工单与客户归属后只读返回资料、余额和业务历史，不返回照片、不显示封存／激活操作。审核结果写入数据库并由余额状态机统一生效。
门店在已通过的充值或核销工单详情页可提交一次作废申请，必须填写原因并二次确认。提交后工单显示为作废审核中，次数在审核通过前保持不变；总部或运营批准后才将工单标记为已作废并显示“客户次数已恢复”。总部／运营显示审核说明与审核操作；门店仅显示审核结果及作废申请入口。留言记录固定展示“门店原申请、总部原审核、门店作废申请、总部作废审核”四项，未填写的内容显示“无”。
`auth-ui.js` 按总部、运营、门店和老师路由白名单隐藏无权菜单并阻止直接串页；运营菜单只有本人首页和两个审核页，白名单另保留由审核链接进入的客户、充值与核销只读详情页；门店不能进入审核、管理或其他门店详情。
总部、运营和门店的会话、首页、侧栏与数据范围分别处理，后端接口仍会再次校验权限。

充值查询和核销查询都提供门店、客户和项目名称条件，并在结果中始终显示项目名称；不使用生日作为历史记录查询条件。
客户条件可在“选择现有客户”和“手动输入姓名”之间切换：下拉选择按客户编号精确查询；手动姓名匹配会在候选提示和结果中显示全部同名客户，并通过客户编号和所属门店区分。客户编号可以进入客户详情。
同名客户在结果和详情中的显示名称必须追加顺序号，例如“张静1、张静2、张静3、张静4”，
使每个不同客户编号在视觉上也能直接区分；手动输入原姓名“张静”会一次返回全部同名客户。
充值编号进入独立的 `recharge-detail.html`，核销编号进入独立的 `verification-detail.html`；
两个详情页分别显示完整业务字段、原始记录和上一版本、异常审核及操作审计，核销详情另显示现场照片权限和设备信号结果。
充值详情页“版本与原始记录”表中的每个版本编号都可以点击；点击后在同一充值详情页加载该版本，并标记“正在查看”，
其他历史版本和当前有效版本继续同时保留在版本表中。
核销详情页采用相同规则：V1、V2及以后所有核销版本编号均为链接，点击后加载对应核销版本并保留原照片证据关联。

所有充值和核销（消耗）信息必须绑定并显示门店。查询结果、客户档案、记录详情、异常审核及每一个历史版本都保留门店编号和名称；
正式系统创建记录时门店字段不可为空，并保存发生时的门店名称快照。

每一条核销记录必须有现场照片。照片未拍摄、上传失败、保存失败或完整性校验失败时，核销不得成功、不得扣减次数，
也不得向物理机器发送开放权限信号。查询、客户档案、核销详情和历史版本都显示照片状态；静态原型只显示状态，不保存真实照片。

静态原型中的删除采用软删除：对象状态改为“已停用”，不删除历史充值、核销、客户或统计引用。
新增和停用操作在当前页面会话中立即生效；刷新页面后恢复示例数据。正式部署时由后端数据库持久化并记录账号、姓名、时间和审计日志。

总部首页使用 `staffAccount` v39 的 `getHqDashboard` 从 PostgreSQL 汇总真实数据，不再使用空数据源、按天比例缩放或虚构的环比百分比。默认范围是上海时区当天及此前29个自然日；自定义范围最多366日。页面只统计当前仍为 `APPROVED` 的工单，作废通过后原单成为 `VOIDED` 并从其原提交周期汇总中移除。按门店统计从门店主表完整列出所有门店，所选日期内没有有效业务的门店也显示名称、短编号和数值 0。

门店项目对比图的纵轴显示“次数”，从0开始，并根据当前筛选数据自动采用1、2、5及其10倍数量级的易读刻度。
纵轴上限会随筛选结果动态变化，但同一张图中的充值柱和核销柱始终共用同一纵轴；横向滚动时纵轴固定可见。

时间周期使用自然日历口径：“本年截至今天”为当年1月1日至系统当天；第一季度为1—3月、第二季度为4—6月、
第三季度为7—9月、第四季度为10—12月。已结束季度统计完整季度，当前季度截止到今天，尚未开始的季度显示暂无数据。
另提供“本周（周一至今天）”和“本月（1日至今天）”。所有业绩统计均包含活跃和已存档客户，只按业务记录有效性与所选时间周期汇总；
客户存档或恢复不会追溯改变历史有效充值、核销和业绩。
选择周期后自动填写开始和结束日期；手动修改日期时自动切换为自定义周期。

全局视图是默认首页，只提供时间周期、开始日期和结束日期调整，并固定显示按门店、按项目和按老师三张图。
三张全局统计图采用一图一行的纵向布局：门店统计一行、项目统计一行、老师统计一行；每张图内部继续支持横向滚动。每个分类对象在横轴完整显示名称和短编号，充值／核销的每根柱直接标出数值，不再用省略号截断对象名称。
全局视图不显示“充值与核销趋势”图，也不生成任何合成趋势。门店、项目、老师和分类方式不放在全局首页；
具体对象及逐笔业务通过管理、客户查询、充值查询和核销查询页面查看。
全局“完整排名”表右上角提供分类维度下拉框，可以在门店、老师和项目之间切换并立即重新计算排名与占比；
老师维度只统计有效核销次数，有效充值列显示为“—”。
