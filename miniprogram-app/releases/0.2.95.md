## 本版内容

- LASER-BLE 下行恢复为固定最多 20 字节顺序分片；不请求或依赖更大的 ATT MTU，每条完整 JSON 仅在最后追加一个 LF，分片之间不增加固定延时。
- 页面在任何异步资格检查前先占用同步启动锁，并用会话代数隔离关闭后的迟到回调，快速重复点击或旧流程不能启动第二条授权链路。
- `auth` 任一分片写入失败后不切换写入方式重发，避免设备可能已收到部分授权时产生重复授权。
- 生产 `faceRecognition v121` 使用旧 token 做原子比较更新；并发签发只有一个请求能成功，唯一键冲突直接返回竞争错误，不再递归签发第二个 token。
- 精简 `q=1/q=2/q=3` 报文、二维码编号、精确广播名、`LASER-BLE` 类型、FFE0／FFE1、nonce、次数、有效期、凯撒签名和真实工作状态校验均未改变。

## 设备端要求

设备继续按字节流拼接 20 字节分片，直到完整 JSON 与最终 LF 后再解析；一条完整请求只回复一次。`auth` 只处理一次，重复或过期 token 必须拒绝。详细规则见 [LASER-BLE 扫码核销设备交互协议 V4.1](../../output/pdf/Lusizhuoer_BLE_Device_Interaction_Protocol_V4.1.pdf) 和 [固定 20 字节设备端要求（一页）](../../output/pdf/Lusizhuoer_BLE_Fixed_20_Byte_Device_Requirements_One_Page.pdf)。
