## 平台信息处理项目

以下用途可用于填写相应字段。平台合并“照片或视频”的类别时仍应写明本程序实际只处理图片。摄像头用途按后台检测项及可自主补充项目填写，不能把 `chooseMedia` 加进只接受特定接口的 `requiredPrivateInfos` 配置。

| 平台类别 | 填写用途 |
| --- | --- |
| 收集你的手机号 | 用于总部、门店和老师员工账号的登录验证、既有账号识别及账号安全管理。使用微信手机号登录时，由你主动授权获取手机号。 |
| 收集你选中的照片或视频信息 | 本小程序仅处理图片，用于客户建档、人脸核验、核销现场与补充照片留存，以及总部上传项目凭证背景图片。客户照片由经授权的业务人员在相应功能中拍摄或选择上传。 |
| 访问你的摄像头 | 在你主动拍照或扫码时，用于拍摄客户建档及核销照片、补充业务照片，以及扫描美容设备二维码。 |
| 访问你的蓝牙 | 在核销设备授权流程中，用于发现、连接现场美容设备，核对设备身份、发送本次服务授权并接收设备工作状态。 |
| 使用你的相册（仅写入）权限 | 在你主动点击保存时，将有权查看的业务照片、工单凭证图片或项目凭证样例保存到设备相册。 |

姓名、生日、客户编号、所属门店、服务项目、次数与余额、业务时间、备注、留言、评分，以及人脸信息，不能因为不是微信隐私 API 直接返回就省略。应在后台可选信息类别或补充文档中声明。

当前业务源码未发现昵称头像、定位、通讯录、日历、麦克风、微信运动、发票、车牌或剪贴板读写功能，不应照着示例表全选。蓝牙设备标识不应被误写成收集手机通讯录或定位。平台及所接入 SDK 的实际信息处理仍需按其现行说明核对；本次没有声称完成依赖全部内部采集行为审计。

## 插件与服务方

- 当前 `app.json` 没有声明微信第三方插件；不能把腾讯云 SDK 当作“客服助手”插件填写。
- 已接入 `@cloudbase/js-sdk 3.7.1` 和微信适配器 `1.3.1`，用于身份认证及访问后端服务。认证、数据库、云函数和私有对象存储使用腾讯云服务。
- 服务端调用腾讯云人脸识别服务，处理客户照片和人脸档案，进行质量／活体检查及所选客户 1:1 比对；建档接口还传递客户姓名和客户对应的人员标识。不能声明“照片仅在本地处理”或“不向服务方传输”。
- 腾讯云不是本小程序的当然开发主体，也不能据此认定腾讯云是代开发服务商。运营主体填微信认证全称；受托服务方的法定名称、处理范围、合同与隐私说明需按实际采购关系核对。独立门店与总部、老师之间的数据处理关系也需按实际组织／合同确定。

## 提交前尚缺的信息与安排

1. 微信认证主体全称，以及确实有人受理的隐私反馈邮箱或电话。
2. 分别确定员工账号、客户资料、建档照、人脸档案、核销／补充照片、工单、日志及备份的实际保留规则和删除流程。代码中的授权有效期、临时图片链接有效期、本地缓存有效期都不等于云端数据保存期限；不能直接套用示例 180 天，也不能把封存当成删除。
3. 当前建档页由业务人员勾选“已取得客户明确授权”，服务端检查 `consent: true`。这不证明客户本人已获得完整告知并作出单独同意，也不证明已取得人脸经互联网传输到云端的相应同意。需核对客户实际知情材料、同意记录、撤回渠道、保存期限及个人信息保护影响评估。
4. 当前核销流程要求客户人脸核验，代码没有提供非人脸替代流程。现行办法对存在同等业务验证方式、或个人不同意使用人脸的情形作出替代方式要求；应由运营主体结合实际业务和专业法律意见落实合理便捷的替代安排。不能只在隐私文案中虚写一个尚不存在的方案。本轮没有擅自绕过核销校验。
5. 若服务不满十四周岁客户，需确认监护人同意和专门规则；不能仅凭生日字段推定已完成。确认后再填写实际生效日期。

这些是与代码和本次隐私申报直接相关的缺口，不是对整套业务作出的法律合规结论。
