# 小程序管理分页与客户留言高度

本轮仅改小程序老师／门店管理分页模板与样式，以及客户主页留言展示样式；目录和客户主页 JS、权限、数据库、核销、照片链路与旧版 Web 均未改动。

## 最终效果

- 手机管理分页为两组紧凑控件，平板为同排居中；输入框和按钮等高，键盘完成调用已有跳页校验。查询、活跃、封存分页互不联动，十条完整展开，末页按实收缩。
- 按用户最新澄清撤回四倍留言高度。手机空框 120→180rpx，列表最小高度 180rpx、上限仍为 620rpx；iPad 恢复空框 90px、列表上限 210px，明确清除手机最小高度。输入框、发送和消息加载不变。

## 验证

- `node --test tests/*.test.js`：607 项通过，0 失败；包含核销、体验／补录、扣次、BLE、照片、审核、充值和权限原回归。
- 新增 teacher/store VM 分页隔离测试：下一页、最后一页、独立查询和封存页码、非法跳页与加载锁定。
- `tests/build-directory-pager-preview.js` 创建临时离线项目，十个生产文件逐字节复制并保存 SHA-256 清单；只读假 API，无云 SDK、真实账号和业务写入。
- 原生管理分页检查：320／390／430 手机（含三位页数、末页及键盘跳页），768／1024 竖屏 iPad。834 iPad 检查客户留言。
- 最终留言高度已在 430 手机和 834 iPad 重新编译检查，完整卡片与发送按钮可达；此前四倍高度截图不代表最终效果。
- 3.17.1 灰度基础库偶发 `clickCheckTask`／`Symbol.iterator` 框架异常，不能写成运行期零错误；最终留言截图时仅三条基础库／预加载警告。大 iPad 横屏切换被用户操作中断，本轮未完成横屏复核，未声称全设备全路由验收。
- JavaScript 语法及 `git diff --check` 检查通过。用户原有项目配置和图片不纳入本次提交。

本轮无 SQL、云函数、静态网站部署或小程序上传；源码推送不等于发布。
