# 小程序内页布局优化 · 2026-09-05

承接[三类账号、26 页检查报告](2026-09-05-miniprogram-role-layout-audit.md)，按用户“优化”的指令实施。保留暖象牙白、香槟金、深咖品牌配色，范围为原生微信小程序；服务端角色、数据范围、审核与核销规则没有调整。

## 已实施

| 原检查项 | 本轮变化 |
| --- | --- |
| A1 审核失败被遮挡 | 提交中和错误直接显示在确认框内；失败保留留言和当前工单，提交中禁止重复点击。 |
| A2 照片操作截字 | 手机“查看原图”独占一行，保存／转发并排；768px 平板四张照片的操作逐行排列，保留每张照片的全部操作。 |
| A3 评价权限反馈 | 服务端返回 FORBIDDEN 时显示查看范围说明，不再提示无效重试；网络失败仍可重试。跨老师历史查看权没有扩展到评价。 |
| A4 文字与额度可读性 | 一般查询／审核手机文字提高至 24rpx，分页按钮提高至 80rpx；老师当月额度使用内容自适应列宽，数字完整显示，手机只在额度卡内横滑。 |
| A5 办理身份 | 门店账号在首张业务卡看到实际门店名称；老师选择门店后以只读字段显示本人，门店仍可选业务老师。 |
| A6 标题与卡片 | 内页统一透明底深咖标题；修正模板内容标题层级、客户摘要四列和老师页返回按钮；办理卡取消不必要的强制等高。 |
| A7 改密页 | 使用当前 v4 背景、中等圆角和全宽主按钮；密码规则显示在输入框外，保留各流程原有校验。 |
| A8 长名称与提交反馈 | 平板项目／产品卡为完整名称让出整行；产品购买成功或恢复后显示完整原单号与下一步提示。 |
| A9 按钮尺寸 | 四类创建页按钮约束在各自网格内，返回／新增／状态按钮按用途确定宽度，消除原生默认宽度挤压。 |
| A10 完整时间 | 产品购买的提交、审核时间各占一行；客户近期信息在平板按两列展示。 |

老师详情在 700–1099px 使用全宽当月额度，1100px 以上才采用左右工作区，避免 iPad 多层分栏挤压。每个项目仍为一行，配置、单独充值、删除配置和额度历史均保留。

## 验证

- `node --test tests/*.test.js`：288 项通过。新增审核错误保留／重复点击防护，以及评价拒绝、网络失败、跨工单旧响应四项行为测试；调整旧的固定字号／网格断言，与新的视觉规范一致。
- 修改的业务页面 JavaScript 语法与 `git diff --check` 通过。
- 微信开发者工具使用独立项目、实际 WXML／WXSS 和模拟业务数据进行手机 390px、iPad 768px 布局检查。所有业务事件均为空处理，不读取生产账号、照片或业务数据，不提交真实审核／充值／核销。另以 320px 窄屏复核四类创建页、改密、老师额度、购买成功和审核失败共八个场景；四类创建按钮等高、互不重叠且未越出页面。
- 权限结论来自既有角色矩阵及本地回归；本轮没有三类真实账号在线验收，也没有替代真机相机、相册或 BLE 验收。

实测修复对比：

| 项目 | 优化前 | 优化后 |
| --- | --- | --- |
| 手机门店创建按钮 | 两个按钮各 184px，约重叠 30px | 148px／222px，高 45px，独立间距 |
| 手机照片操作 | 每个约 50px 宽、31px 高 | 查看原图 158.5px，保存／转发各 77.25px，高 41px |
| 768px 平板照片操作 | 每个约 42px 宽，四字标签被截断 | 每个 138.5px 宽、42px 高，完整标签 |
| 768px 平板老师额度 | `99999 次` 显示为省略号 | 16px 数字，完整显示，列宽按内容分配 |
