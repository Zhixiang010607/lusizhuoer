# 小程序紧凑布局与卡片层次优化

日期：2026-09-06。用户确认实施五项视觉建议，保留现有品牌配色，并要求实际截图。

## 改动

- 老师／门店首页和总部进入的门店主页：时间快捷入口统一为今天、本周、本月、更多；更多使用原生选择器，保留本季度、本年、全部、自定义，选定后显示周期名称。自定义日期同排，保留应用按钮。
- 核销、充值、体验、退费四个标签同排，保留次数、服务端数据范围和分页。门店的体验仅为历史查询，未增加办理入口。
- 客户查询的六项统计合成一张概览，当前结果／活跃／封存突出显示，三类业务阶段作为次行。摘要使用短标签，筛选参数和结果阶段文案未变。
- 活跃预警、余次预警、评价分析的规则默认收起，点击规则说明展开；没有结果时不显示导出按钮。导出仍为当前条件下全部结果、按门店分组，原有 1000 条上限与鉴权保持。
- 两类预警都无结果时只保留一条全宽空提示；有结果时仍保留两个独立分类和分页，以细分隔线替代嵌套卡框。联系方式去掉重复内框，普通卡片取消阴影，标题字重收紧。

## 验证范围

314 项 Node 回归通过，包含实际页面控制器的三角色日期切换、自定义应用、非法选项忽略和三页规则展开不改变筛选／分页状态。已有权限、查询、导出、页面契约继续通过；只更新与本次用户决定相冲突的布局断言。

微信开发者工具 390×753 手机视口完成 27 个隔离原生展示场景：老师／门店首页、总部进入门店主页，另有总部／门店各自的客户查询、两类预警和评价分析，每页覆盖 0、3、6 条。检查时间／业务控件同排、控件边界、汇总高度、规则开合及空结果导出隐藏，无页面异常事件。

工作台使用实际页面控制器和隔离服务；查询页使用实际 WXML／WXSS、初始数据和规则开合，其他业务请求以隔离桩替代，故不把展示回归当作生产账号查询验收。全部截图为示例门店／客户／工单，无生产数据写入。电脑锁屏使 iPad 模拟器切换未能继续；平板保留独立物理像素断点与已有契约测试，真机／iPad 本轮未验收。
