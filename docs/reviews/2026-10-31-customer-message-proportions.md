# 客户主页：展示优先、紧凑输入与近期信息 2×2

取代同日上一轮仅改展示高度、不动输入卡的方案。当前修改仅涉及小程序客户主页 WXML/WXSS、回归测试和规则基线。

## 最终规则

- 去掉输入区的多余有色外框及内边距，字数／发送按钮同排，输入仅保留一个框。局部双类选择器覆盖全局 `page .textarea`，修复 iPad 实际被 120px 通用最小高度撑大的问题；不使用全局样式修改影响其他表单。
- 手机输入 96rpx，发送按钮 80rpx；iPad 输入 60px，发送按钮 40px。空框／加载状态手机 220rpx、iPad 128px；有留言时手机按内容 300—840rpx，iPad 160—300px。长列表保留内滚动及加载更早留言，不能通过减小消息字数或删掉历史来改变版式。
- 近期信息固定 2×2，移除旧的 `max-width:360px` 单列规则。四个字段、资料生日、状态操作、历史业务及表格均保留。
- 客户主页 JavaScript 与提交接口未变；核销／体验／补录、人脸、照片、BLE、扣次、充值、审核、数据库和 Web 均未改动。

## 证据与限制

- `node --test tests/*.test.js`：608 项通过、0 失败，包含全部现有业务回归。新增展示／输入比例、平板选择器优先级和全部近期信息网格均为两列的断言；更新旧的全宽发送／嵌套输入卡视觉契约。
- 原生离线样例逐字节复用十个生产文件，无云 SDK，无真实客户或业务写入。375 手机核对空态完整卡片；834 iPad 核对实际 60px 输入、128px 空框、100 字中文／计数、启用与禁用发送按钮，未点击提交。320 手机检查长单条留言，随后在原生界面观察到最终 2×2；保存时窗口返回入口，误存图片已排除，不能当作最终截图证据。
- 用户追加的“多留言时再长一点”通过独立 `has-messages` 类限定；最终多留言滚动上限及其余尺寸尚未完成全套原生复核，不能声称全设备／全路由视觉验收。工具多次遇到窗口切换和连接超时；正式项目窗口不作为离线验证证据。3.17.1 基础库存在原有预加载／worker 警告。
