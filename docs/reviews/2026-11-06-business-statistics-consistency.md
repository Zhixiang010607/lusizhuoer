# 2026-11-06 数据展示、内部账本与跨端一致性检查

本轮完成源码修正、线上只读对账、隔离 PostgreSQL 测试与真实客户端界面验收。生产数据库无写入；092、faceRecognition v141、Web 与小程序均未在本轮上线。Git 推送与部署分开记录。

## 统一后的语义

| 数据 | 权威口径 | 已核对的展示／读取 |
| --- | --- | --- |
| 历史充值 | APPROVED、NEW 的 unit_count 求和，不减退费 | 总部／门店／老师总览与明细、客户查询、门店活跃／封存客户、客户主页、照片概要、导出 |
| 历史正常核销 | APPROVED、NORMAL＋SUPPLEMENT 的 unit_count 求和 | 主页、查询、项目／客户统计、老师归属统计、PDF |
| 体验 | APPROVED、EXPERIENCE 独立计数，不扣客户购买余额 | 独立体验列、老师额度与有效业务统计 |
| 退费 | APPROVED、REFUND 独立计数 | 退费查询、主页及项目／客户汇总、PDF；不倒减历史充值 |
| 当前余额／净开卡 | 原数据库余额刷新、审核及可退风控算法 | 原余额、扣次、可退额度、余次预警继续使用净口径，不拿历史充值替代 |
| 业务阶段 | 历史已通过 NEW 充值＋NORMAL／SUPPLEMENT；退费不抹去历史 | 客户列表、筛选、分类人数和主页读取同一持久化阶段；需 092 |
| 实物产品 | 购买与充值赠送分别按其有效来源统计 | 动态产品类目、赠品末行、产品查询、客户产品汇总；不混入项目四项次数 |

各统计默认只计有效业务；客户业务记录页保留待审、驳回等审计明细，因此“记录条数”与“有效次数”不是同一字段。次数按 unit_count 求和，不按工单行数。客户业务阶段有充值才进入两个“已充值”分类；只有体验、购买或赠品仍不算历史充值。

时间沿用上海自然日与提交时间，区间采用开始日包含、结束日次日零点不包含；审核通过日期不挪动业务归属日。全历史需显式请求。总部／门店／老师各自授权范围保持原样；组长总览只含当前成员，客户运营仍按当前成员＋本人关联客户范围。跨店工单按真实办理门店统计，客户最初建档门店不替代工单门店。

## 找到并修正的差异

1. 客户查询、门店首页活跃／封存客户及照片概要曾直接读取净开卡缓存当作累计充值。v141 改为已通过 NEW 历史次数；数据库净缓存、余额和风控未改。
2. 客户主页及照片概要的累计核销曾包含体验，而体验另有单列。改为 NORMAL＋SUPPLEMENT，避免重复理解为普通核销。数据库历史总服务缓存继续包含体验，保留原存储语义。
3. Web 客户项目汇总补齐独立“累计退费”列，与小程序五列一致。
4. 总部 PDF 的项目合计从本次完整项目行求和；排名占比从本次完整排名行计算。遇到重复对象或所选指标明细与服务端合计不一致，拒绝导出并要求重读。跨多个请求分页读取仍不是同一个数据库事务快照；若数据变化未导致所校验指标合计变化，本校验不能证明整份报表来自同一时刻。
5. Web 排名规则文字由旧“100条”改为实际每页10条；占比标题随排序指标显示“充值／核销／体验／退费占比”。
6. 用户确认业务阶段按历史有效业务划分。新增 092，仅替换 refresh_customer_balance 的阶段 CASE，其他函数体一致；回填只写 customer_process_status，不调用余额刷新。全额退费后保留历史充值阶段。
7. 客户五类业务记录统一每页10条，服务端同一条 SQL 返回各类别的总数、夹取后的页码及本页数据；每页序号从1开始。旧 historyLimit／游标协议保留以支持后端先上线；新客户端要求 pageSize=10，后端未升级时明确报错。新旧协议不能混用。

## 线上只读核对

使用已固定环境的 SELECT-only 工具，读取真实账本、表结构、约束、28个相关触发器及48个相关函数，并保存私有回执。没有在生产调用余额刷新、体验重置、审核或提交函数。

- 同一 SQL 快照内：总部四项全局合计、门店维度、项目维度和老师维度（含未指定老师）逐项相等。
- 账本到项目余额、客户次数缓存、最新时间缓存均无差异；没有负余额、无效次数、孤立业务引用或重复幂等编号。
- 核对7个关键数据库可执行函数体与当前已上线迁移来源一致，忽略注释／空白差异。092 尚未执行，线上余额刷新函数仍为此前044版本，此项不能视为092部署验收。
- 092只读预览预计当前需改阶段的客户数为0；这不代表未来全额退费场景不需要新规则。现网没有已通过退费，退费边界由隔离数据库实际执行覆盖。
- 可重复执行的无个人信息审计：[001-business-statistics-readonly.sql](../../database/audits/001-business-statistics-readonly.sql)。其中历史体验／退费客户数量为盘点项，不应按非零判为故障。
