# 微信小程序上传线路加速记录

## 结论

小程序本地编译和打包只需数秒，长期等待发生在微信开发者工具把加密代码包上传到腾讯 COS 的阶段。开发者工具会把同一个 COS 域名解析到多条线路，但本机到这些线路的实际上传质量差异很大。

仓库新增 `scripts/wechat_upload_fast.py`。它会：

1. 并行检查当前 COS IPv4 线路是否可达；
2. 启动只支持 HTTPS CONNECT 的本地转发代理；
3. 重启微信开发者工具，并只向其注入 `HTTPS_PROXY`；
4. 让开发者工具自身的官方上传流程继续完成编译、签名和上传。

代理不解密、不修改代码包，也不保存微信登录信息或 COS 签名。普通 HTTP 请求不经过该代理。

## 实测

- 原 `0.2.80` 开发版上传：约 `944.6` 秒。
- 自动选线后的同项目预览上传：`154.87` 秒，官方 CLI 返回 `✔ preview`。
- 同一时间强制走另一条 `.84` 线路：等待 `250.84` 秒仍未完成，测试被主动终止。

本次成功预览比原上传记录快约 `6.1` 倍。预览与开发版上传使用的是同一个 COS 上传模块，因此后续上传可使用同一脚本；但腾讯线路状态会变化，不能承诺每次都保持完全相同的耗时。

## 使用方法

只检查当前线路：

```bash
python3 scripts/wechat_upload_fast.py check
```

生成预览：

```bash
python3 scripts/wechat_upload_fast.py preview
```

上传开发版：

```bash
python3 scripts/wechat_upload_fast.py upload \
  --version 0.2.81 \
  --desc "本次开发版说明"
```

如需排查指定线路，可显式传入当前 DNS 返回并且测试可达的 IP：

```bash
python3 scripts/wechat_upload_fast.py --ip 117.68.20.85 preview
```

## 包体侧现状

项目已启用 WXML、WXSS 和 JavaScript 压缩、关闭上传 Source Map、忽略 `node_modules`、类型声明、映射文件及未引用图片，并把三个报表重复字体合并成一个按需分包。当前预览回执为主包约 `1.7 MB`、总包约 `3.2 MB`，其中共用中文 PDF 字体约 `746 KB`。继续大幅缩包需要改动报表字体或资源加载方案，会影响离线导出能力，不能作为纯上传工具优化直接删除。

微信官方上传接口提交的是完整版本快照，并不提供“只上传本次修改文件”的增量发布选项。因此当前有效优化重点是稳定选择可用上传线路，而不是跳过未修改文件。

## 发布状态

本记录只确认加速脚本生成预览成功，没有上传新的开发版本、没有设置体验版、没有提交审核或正式发布。当前最后确认上传成功的开发版仍为 `0.2.80`。
