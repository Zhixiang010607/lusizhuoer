# 新增项目自动沿用 HC-08 协议

2026-11-23 用户确认：原三个项目是固定组，配置与行为保持不变；以后新增项目是独立自动组，完整沿用同一交互，不再逐项目修改代码。

## 两组配置

原组继续使用原来的三项冻结配置及原三类型判断：魔法柔肤 `LASER-BLE`、海洋之蕴／海洋之韵 `haiyangzhiyun`、露思康辰 `lusikangcheng`。原项目名称到类型的映射函数也保留原字节。

新组不维护项目名称名单。服务端仍通过原函数将新项目名转成小写无声调拼音／数字，最长 128 位；小程序及服务端的新增分支自动识别这个类型。新增独立冻结的 GATT 参数与原组完全相同：Service FFE0、Write／Notify FFE1、优先 writeNoResponse。类型名符合自动组的项目使用 LA 加 12 位十六进制编号、LA-末六位广播名，并从首包起使用相同精简协议。原组判断先执行且短路，不会进入新组分支。

新组完整沿用 q=1 信息读取、q=2 授权、q=3 状态补查、最多 20 字节顺序分片、LF 帧、5 秒单次读取补发、10 秒响应窗口，以及现有 nonce 凯撒计算。没有为新组复制另一套核销状态机，也没有改密码算法、授权自动重发策略、90 秒资格、30 秒授权、原子预留、状态 2 后确认及唯一扣次／工单。旧的非自动类型（例如含连字符的历史类型）仍保留完整协议兼容路径。

设备端仍须按原协议实现；本次只改变我们系统对未来项目的自动选型，不声称能接入任意不兼容的设备。

## 验收

- 修改前从 v145／0.3.67 的真实协议模拟器捕获独立基线，含实际 20 字节分片、服务端授权及唯一确认调用。三个类型归一化后的 SHA-256 均为 `741ff1a92c8396dfca0e9772d9d88c8b19f7586ef326a0299e33b4985325292a`，见 `tests/fixtures/ble-existing-three-wire-v145.json`。
- 修改后原三类型逐项与该旧基线一致。四个没有登记在源码名单的新类型也与同一基线一致，分别只签发一次授权、确认一次工单。
- 新组还验证了多服务干扰、16／128 位 UUID、残片后一次 q=1 补查，以及错误类型、NCM 编号、广播名、状态和 nonce 拒绝。原 3 类型测试没有修改。
- 独立源码比较：238 个既有服务端函数中，仅授权函数的类型选择增加新分支；把该选择还原后函数正文逐字节一致。23 个小程序会话方法中，仅协议发现、信息读取、身份验证三个入口增加选择；其余 20 个方法逐字节不变。三项原冻结 GATT、两端原三类型判断、项目类型生成函数逐字节不变。
- 850 项全量回归和 361 份 JavaScript 语法检查通过，包含 Web、权限、照片、统计、充值、核销、预留与防重回归。没有写生产业务数据来测试，没有做真实硬件联调。
