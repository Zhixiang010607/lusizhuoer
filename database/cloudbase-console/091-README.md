# 091：老师兼任组长与只读成员范围

此迁移新增三张组长／成员／审计表和专用函数，不改写已有人员、客户、工单、余额或考勤日报，不自动任命任何老师。业务身份仍只有总部、门店、老师，组长仍是老师。

## 执行顺序

1. 先运行 [091-preview.sql](091-preview.sql)，精确确认正式环境、数据库及三个基础数据库角色。首次执行时三张小组表应不存在；如已存在，先核对迁移状态，不重复运行创建脚本。
2. 按仓库生产备份规则，通过 scripts/cloudbase-pg-change.js 对全部公共基础表和序列做一致性快照、验证行数，并在同一次门禁中执行 [091-01-teacher-team-leadership.sql](091-01-teacher-team-leadership.sql)。该文件是可完整复制的独立 SQL；不得绕过备份门禁直接写生产数据库。备份失败或校验不一致时停止。
3. 独立运行 [091-readonly-verify.sql](091-readonly-verify.sql)，九项检查必须全部 READY；另与备份逐表核对原有业务记录、原序列、原函数和原约束未变化。新表、函数、触发器和一个新审计序列属于本迁移新增对象。
4. 原地部署 staffAccount v100、faceRecognition v140 与 customerRating v9，分别确认运行时版本和下载源码一致；核销照片与老师创建函数不因本次组长能力重复部署；v9 评价仅增加“组内＋自己”客户集合内的只读分析，不增加评价写入或二维码权限。
5. 最后更新总部 Web 和小程序。网页仍仅总部登录；老师组长本人只在小程序使用只读运营入口。

## 权限及事务约束

只有总部可以任免、添加或移除成员。写入函数按可信云函数提供的当前认证 UID 重查在职总部，客户端不能提供操作人。所有组关系变更使用同一事务级锁，成员主键确保全局唯一归属；数据库触发器同时拒绝组长作为成员、添加本人和直接跨组改绑。

取消组长会在同一事务自动释放全部成员，并写入逐成员释放审计及任免审计。重新任命不会恢复旧成员。成员资料与既有业务记录始终保留。两个只读范围函数按当前组长、账号／主档状态和当前成员关系判断，不依赖客户端缓存；移除成员或取消组长后，新请求立即失去相应范围。

匿名和已登录客户端数据库角色不能读写这些表或执行函数；service_role 只能直接只读表，并通过精确总部写入函数修改成员关系。组长不能改项目额度、密码、人员状态或审核业务。原老师本人业务与客户权限不扩展。

## 验证与回退

tests/verify-teacher-team-database.cjs 支持本地 PGlite 隔离测试，只接受本地测试运行时路径，不能连接 CloudBase 或任何生产数据库。仓库普通回归还覆盖原核销、扣次、照片、BLE、审核和权限边界。

回退客户端／云函数时保留新表和审计，不自动删表或解除成员，不重跑旧破坏性迁移。任何生产回退写入仍需另一次新鲜完整备份。本文和源码包不代表迁移或部署已在生产执行。
