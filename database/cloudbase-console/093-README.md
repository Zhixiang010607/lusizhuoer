# 093：封存老师自动退组与所属组长姓名

最终规则：普通老师封存时退出原组；组长封存时取消组长资格并释放全部成员。恢复账号不自动恢复归属或资格。**封存关联的退组、取消资格和释放不额外生成小组操作记录**；正常手动任免、添加／移除的既有行为保持，历史业务、考勤、日报和余额保持。

执行顺序：

1. 执行 [093-preview.sql](093-preview.sql)。确认环境；inactive_bindings必须为0，migration_already_present必须为false。如已有迁移，不重复执行；如有历史无效关系，先独立预览处理，不猜测操作人或写假记录。
2. 通过 `scripts/cloudbase-pg-change.js` 完整备份全部public基础表和当前序列值，验证无行数差异后，在同一门禁执行 [093-01-teacher-archive-team-release.sql](093-01-teacher-archive-team-release.sql)。禁止绕过备份门禁直接写生产。
3. 独立执行 [093-readonly-verify.sql](093-readonly-verify.sql)，五项READY；与完整备份逐表、逐序列比较，迁移本身不改任何业务行或归组行。
4. 部署并回下载验收 staffAccount v101、faceRecognition v142，然后更新小程序与总部Web。不得用生产封存、分配或新建业务来代替隔离验收。

新状态函数重新验证总部UID，在原组关系事务锁下先解除绑定、必要时取消组长，再更新老师状态，并沿用既有账号同步触发器。原认证层禁用与失败补偿继续由云函数处理。声明式延迟约束拒绝绕过原子入口造成“已封存仍占组”的数据库写入；直接维护已归组人员时同样应使用总部专用状态函数，不手工只改一个状态字段。激活不隐式重新任命或分配。

名称函数仅service_role可执行；云函数先确认本人／总部／当前成员只读范围，再取姓名。页面只显示普通文字，不增加组长主页、跨组或写入权限。上线前已完成隔离SQL的撤销、恢复、失败回滚和不新增小组记录检查。

本文件与源码包不等于已执行。真实生产状态以独立部署回执为准。
