# customerRating

当前版本：`v7`

客户评价独立服务。它只负责核销/体验核销完成后的评价链接签发、公开评价提交和员工端只读查询，不参与人脸验证、BLE 授权、扣次或工单状态变更。v7 把评价分析的汇总、图表计数和当前页合并到同一条 PostgreSQL 语句，并为最多 1000 单的完整导出提供单语句快照；公开提交在 `UPDATE` 已提交但 CloudBase 返回空 `RETURNING` 时，会按评价 ID、令牌版本和令牌摘要有界重读并确认实际评分，避免把成功的一次性评价误报为失败。v6 的筛选与最低分规则、v5 的扫码项目／服务时间上下文、既有永久未评价链接、一次提交和权限规则全部保留。

## 动作

- `issueForReceipt`：总部账号可为任意已完成正常／体验核销、门店账号可为本门店已完成正常／体验核销签发评价链接和二维码；老师账号拒绝。`issueForStore` 作为旧客户端兼容别名保留，执行相同权限判断。
- `getForStaff`：总部、所属门店和该工单老师读取评价。
- `getRatingAnalysisOptions`：总部或门店读取其权限范围内历史核销工单实际使用过的门店、项目和老师筛选项。
- `queryRatingAnalysis`：总部或门店按筛选条件分页读取评价工单、最低分、0—5 分分布和评价覆盖率；门店范围由服务端锁定，老师账号拒绝。`exportAll=true` 只为当前完整导出使用，最多返回 1000 单，并让汇总与全部导出行来自同一数据库快照。
- `getPublic`：客户通过不透明令牌读取门店、可选老师、项目名称和本次服务时间等安全评价上下文。
- `submitPublic`：客户一次性提交门店环境、老师服务、整体体验和文字评价。
- `health`：返回版本、页面地址和必要环境变量是否齐全，不返回密钥。

## 环境变量

- 必填：`CLOUDBASE_ENV_ID` 或 `TCB_ENV`。
- 必填：至少 32 字节的 `CUSTOMER_RATING_SIGNING_KEY`。同一未评价工单的重复导出会稳定复用同一条签名链接；数据库只保存 SHA-256 摘要。密钥不得进入客户端、二维码、仓库或日志。
- 必填：`CUSTOMER_RATING_BASE_URL`。填写实际发布后的 `rating.html` 完整 HTTPS 地址；云函数不猜测静态托管域名，地址不得包含账号或密码信息。

CloudBase 控制台必须开启“匿名登录”，并让匿名角色具备云函数网关调用权限。评价页在没有现有会话时会先建立匿名会话；函数安全规则对 `customerRating` 使用 `"auth != null"`，同时保留其他业务函数原有的非匿名限制。函数级规则无法按 action 区分，因此员工动作仍由函数内部按当前 UID、账号状态、角色、门店和老师关系重新鉴权，公开动作还必须通过工单签名令牌。不要开放数据库表给匿名角色。

部署前先执行迁移 068 及只读验收，再上传 ZIP。部署后调用 `{ "action": "health" }`，确认返回版本 `v7` 且 `configured=true`；随后分别用门店、老师、总部和未登录客户完成权限回归，并确认总部与所属门店可签发、老师不可签发，扫码填写页可读取正确的项目和服务时间，评价分析的门店范围、最低分归档与完整导出快照正确。
